# 交接文档：154 线上——本地数据库全覆盖 + 新功能代码同步

**目标**：用本地数据库完全替换 154 线上数据库，并把本地最新功能同步到 154 线上。

**执行方**：由另一 Agent 或运维按本文档步骤执行。

---

## 一、前置与物料

1. **本地数据库压缩包（已生成）**  
   - 路径：`lnexam/server/data/lnexam-production.db.gz`（约 212 KB）  
   - 内含：带解析的 2026 主题库、2022 复习、2024 题库等，与本地库一致。

2. **154 线上信息（执行前填好）**  
   - 服务器地址：`[154]`（如 `154.x.x.x` 或实际 hostname）  
   - SSH 用户：`[USER]`  
   - 线上项目根目录：`[REMOTE_ROOT]`（如 `/home/xxx/lnexam` 或 `/app`）  
   - 线上数据目录：`[REMOTE_DATA_DIR]`（如 `[REMOTE_ROOT]/server/data`）  
   - 停服/启服方式：Docker 容器名 / systemd 服务名 / PM2 应用名 / 直接 node 等

3. **代码同步方式二选一**  
   - **方式 A**：154 上从 Git 拉取（推荐，需先确保本地已 push 到 GitHub）  
   - **方式 B**：本地用 scp/rsync 把整个项目目录同步到 154

## 二、步骤一：代码同步到 154 线上

### 方式 A：154 上从 Git 拉取（推荐）

1. **确认本地已推送到 GitHub**（在本地执行）  
   ```bash
   cd /path/to/lnexam
   git status
   git push origin main
   ```

2. **在 154 服务器上拉取最新代码**（SSH 登录 154 后执行）  
   ```bash
   cd [REMOTE_ROOT]
   git fetch origin
   git pull origin main
   # 如有冲突按提示处理，或由负责人处理
   ```

3. **安装/更新依赖（若 package.json 或 server 依赖有变更）**  
   ```bash
   cd [REMOTE_ROOT]/server
   npm ci --omit=dev
   ```

### 方式 B：本地用 scp/rsync 同步整个项目到 154

在**本地项目根目录**执行（排除 node_modules、.git、本地 data 等）：

```bash
rsync -avz --exclude='node_modules' --exclude='.git' --exclude='server/data/*.db' --exclude='server/data/*.db-*' \
  ./ [USER]@[154]:[REMOTE_ROOT]/
```

然后在 154 上安装依赖：

```bash
cd [REMOTE_ROOT]/server && npm ci --omit=dev
```

## 三、步骤二：用本地数据库完全替换 154 线上数据库

### 1. 上传数据库压缩包到 154

在**本地项目根目录**执行：

```bash
scp server/data/lnexam-production.db.gz [USER]@[154]:/tmp/lnexam-production.db.gz
```

（若用密钥：`scp -i /path/to/key server/data/lnexam-production.db.gz [USER]@[154]:/tmp/`）

### 2. SSH 登录 154

```bash
ssh [USER]@[154]
```

### 3. 在 154 上停止服务

按实际方式执行其一：

- Docker：`docker stop [容器名]`
- systemd：`sudo systemctl stop [服务名]`
- PM2：`pm2 stop [应用名]`
- 直接 Node：`lsof -i :3030` 查 PID 后 `kill <PID>`

### 4. 备份当前线上数据库（建议）

```bash
cp [REMOTE_DATA_DIR]/lnexam.db [REMOTE_DATA_DIR]/lnexam.db.bak.$(date +%Y%m%d-%H%M%S)
```

### 5. 解压并覆盖线上数据库

```bash
gunzip -c /tmp/lnexam-production.db.gz > [REMOTE_DATA_DIR]/lnexam.db
```

### 6. 启动服务

- Docker：`docker start [容器名]`
- systemd：`sudo systemctl start [服务名]`
- PM2：`pm2 start [应用名]`
- 直接 Node：`cd [REMOTE_ROOT]/server && node server.js`（或项目约定命令）

### 7. 清理临时文件（可选）

```bash
rm /tmp/lnexam-production.db.gz
```

## 七、154 当前部署方式（Docker）与“新功能生效”步骤

154 上 lnexam 使用 **Docker** 部署，代码目录为 `/data/disk/lnexam`，容器名 `lnexam`，端口 **3001**（Nginx 反代 lnexam.metaseek.cc → 127.0.0.1:3001），数据卷 `lnexam_lnexam-data` 挂载到容器内 `/app/server/data`。

- **代码已通过 rsync 同步**到 `/data/disk/lnexam` 后，**必须重新构建镜像并重启容器**，新功能（如仪表盘、科目导航等）才会生效。
- 154 上执行 `docker-compose build` 时若出现 **拉取 Docker Hub 超时**（如 `Get "https://registry-1.docker.io/v2/": context deadline exceeded`），则需采用下方「本地构建 + 传镜像」方式。

### 方式一：154 上直接构建（需 154 能访问 Docker Hub）

SSH 登录 154 后：

```bash
cd /data/disk/lnexam
# 确保有端口 3001 的 override（无则创建）
printf 'services:\n  lnexam:\n    ports:\n      - "3001:3030"\n' > docker-compose.override.yml
docker stop lnexam; docker rm lnexam
docker-compose build
docker-compose up -d
```

### 方式二：本地构建 amd64 镜像再传到 154（154 无法拉取 Docker Hub 时）

1. **本地**确保 Docker 已启动，在项目根目录执行：
   ```bash
   cd /Users/liulaoshi/lnexam
   docker buildx build --platform linux/amd64 -t lnexam:amd64 --load .
   docker save lnexam:amd64 | gzip -c > /tmp/lnexam-amd64.tar.gz
   scp -i /Users/liulaoshi/Downloads/mac.pem /tmp/lnexam-amd64.tar.gz ubuntu@154.8.233.137:/tmp/
   ```
2. **154 上**执行：
   ```bash
   gunzip -c /tmp/lnexam-amd64.tar.gz | docker load
   docker tag lnexam:amd64 lnexam:latest
   cd /data/disk/lnexam
   printf 'services:\n  lnexam:\n    ports:\n      - "3001:3030"\n' > docker-compose.override.yml
   docker stop lnexam; docker rm lnexam
   docker-compose up -d
   ```
   （compose 中 image 为 `lnexam:latest`，故需先 `docker tag lnexam:amd64 lnexam:latest`。）

完成上述任一种方式后，访问 https://lnexam.metaseek.cc/dashboard 即可看到新功能。
